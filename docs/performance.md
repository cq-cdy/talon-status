# 性能设计与基准

本文记录性能设计、测量方法和本地结果。微基准用于发现主要成本并防止无证据优化，不构成所有平台或应用的性能保证。

## 范围与实现

优化基线使用相同接口、结果存储和基准程序，消息工厂对非空参数组统一创建 ostringstream。基线测量显示常用消息构造明显高于单纯结果返回的开销；纯字符串和整数也不需要流格式状态。

实现只优化这一实测开销：字符串、常用整数、char、bool、nullptr 和 string_view 的纯参数组直接追加到自有 string，十进制转换使用固定栈缓冲及 unsigned 幅值，安全处理最小负数。缓冲按 numeric_limits 计算，不依赖8位字节。含任何自定义类型、流操纵器或浮点值时，整个参数组仍使用原流路径，保持格式影响、经典 locale 和错误行为。实现没有引入缓存、锁、共享可变数据、线程局部存储或新依赖，也没有改动 StatusOr 的安全存储来换取速度。

正确性通过常用整数类型的 min/max/0/1、-10000..10000 的20,001个值、空指针/嵌入NUL/临时字符串、locale、自定义格式与操纵器进行对照。流和快路径逐项比较完整消息；不是只比较长度或校验和。值与宏的原测试及新增257节点压力链继续运行。

## 方法

GCC 12.3 / libstdc++12，Linux x86_64（WSL2，Intel Core i5-13500H）；STD 使用 C++23，COMPAT 使用 C++11。两者均为 Release 的 `-O3 -DNDEBUG`、严格警告、无 LTO。仅比较同一后端优化前后，不能把不同标准下的两个后端数字当成公平后端排名。

每个用例先预热，再执行100,000次操作，重复7轮取中位数；固定到本机允许的 CPU 0。每种后端执行“前、后、后、前”四次进程运行。表格为两次运行各自中位数的范围，单位 ns/操作。倍率/百分比按两次中位数的均值计算；未计算统计置信区间。

构造结果交给另一翻译单元的 DigestStatus/DigestResult 消费，禁止 LTO，避免整个 Status 构造因只在同一函数读取长度而被消去。`nm` 实际确认 workloads 对两个消费函数保留未定义外部引用。所有用例逐轮校验结果确定性，并核对优化前后 checksum 一致。单次数字包含调用/循环/消费成本，不等于库某条指令或独立方法的延迟。

## 实测结果

| 用例 | STD 前 | STD 后 | COMPAT 前 | COMPAT 后 |
|---|---:|---:|---:|---:|
| 成功整数结果 | 1.14 | 1.14 | 1.34–1.37 | 1.37–1.40 |
| 两种短文字消息交替 | 141.85–142.49 | 6.85–6.96 | 149.81–153.89 | 13.89–14.23 |
| 字符串+有符号整数+无符号整数 | 200.94–208.18 | 32.95–35.91 | 207.86–217.44 | 48.89 |
| 4096字节 string 消息 | 309.18–318.48 | 48.47–51.01 | 312.31–322.34 | 51.17–53.33 |
| 自定义类型+浮点（流路径） | 326.80–334.58 | 318.54–324.66 | 337.89–342.38 | 332.53–334.28 |
| 64层成功传播 | 125.84–154.66 | 116.43–117.60 | 169.75–175.66 | 139.71–144.35 |
| 64层失败传播 | 2194.10–2225.82 | 2011.29–2055.23 | 2192.78–2366.20 | 2077.40–2078.25 |

常用消息三项：STD 耗时约下降83.2%–95.1%（约5.9–20.6倍），COMPAT 约下降77.0%–90.7%（约4.3–10.8倍）。64层失败传播耗时约下降8.0%/8.8%，其中只在叶节点构造一次消息；没有声称错误转移本身获得相同比例的加速。

成功整数结果与流路径不是这次优化目标。成功整数的极小差异、流路径的几个百分点变化和成功链的较大波动，都不足以作一般化性能承诺，也不据此增加复杂优化。以上结果没有显示明显的成功路径回退；仍应在真实工作负载上复测。

## 复现

```sh
cmake -S . -B build-bench -DCMAKE_CXX_COMPILER=g++-12 \
  -DCMAKE_BUILD_TYPE=Release -DTALON_STATUS_BACKEND=STD \
  -DTALON_STATUS_BUILD_BENCHMARKS=ON -DTALON_STATUS_STRICT_WARNINGS=ON
cmake --build build-bench --parallel 4
./build-bench/talon_status_benchmark 100000 7
```

COMPAT 另设 `-DTALON_STATUS_BACKEND=COMPAT -DTALON_STATUS_CXX_STANDARD=11`，使用独立构建目录。Linux 若允许绑定 CPU，可使用 `taskset -c ALLOWED_CPU ...`；应先读取进程允许的 CPU 列表，不能假定容器允许 CPU 0。

建议按前/后/后/前顺序重复，不同时运行编译或其他主动负载，不改变机器电源/频率策略。基准开关默认 OFF，不污染消费端；同时启用测试时加入128次操作的 benchmark_smoke，只验证工具可运行，不把 CI 共享机器的时延作为回归阈值。

## 限制

未测量 macOS/Windows、其他处理器、编译时间、二进制尺寸、缓存冷启动、并发生产负载和 Abseil 性能对比。消息长度/分配器/CPU调度/编译器内联与代码布局会影响结果。性能保持以“不牺牲错误码、消息、资源、异常和宏控制流契约”为前提，不能用本报告承诺实时上界、零分配或所有场景都更快。
